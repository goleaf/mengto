# 19. API Contracts, External Integrations, Webhooks, Payments, and Idempotency

## Principal-agent role

You are the principal Codex implementation agent responsible for making every external and API boundary explicit, typed, authenticated, authorized, timeout-bounded, replay-safe, idempotent, observable, and completely testable without real network access.

## Mission

Audit all public/internal APIs, resources, HTTP clients, vendor SDKs, webhooks, payment flows, external identifiers, retries, timeouts, signatures, error contracts, and side effects. Normalize contracts, prevent raw model/provider leakage, make retries safe, implement replay protection and idempotency, and build deterministic success and failure tests.

This is not an audit-only, documentation-only, planning-only, or review-only task. Discovery and planning are mandatory intermediate phases. After updating the canonical plan, immediately perform the required implementation, tests, review fixes, documentation synchronization, commit, and safe push directly on `main`.

## Domain-specific guardrails

- Do not return raw Eloquent models or raw provider payloads as public contracts.
- Do not retry non-idempotent mutations automatically without provider/internal idempotency support.
- Do not trust client-provided payment amount, currency, owner, tenant, provider status, or successful completion.
- Do not process trusted webhook meaning before verifying the signature and relevant timestamp/replay controls.
- Do not log credentials, authorization headers, signatures, full sensitive payloads, payment secrets, or complete tokens.
- Do not make real provider calls in automated tests.

## Required implementation scope

Complete all applicable work below. Treat the list as a minimum, not as permission to ignore defects discovered in the same scope.

- Inventory and document every API endpoint, consumer, authentication/authorization requirement, request schema, response resource, status code, pagination contract, error shape, and compatibility expectation.
- Replace raw model serialization with explicit API Resources or typed response data, conditionally include only intentionally loaded relations, and eliminate resource-triggered queries.
- Create one explicit client/gateway per substantial provider, use config-owned credentials/base URLs, set connection and total timeouts, validate response structures, and map provider data/errors into typed internal contracts.
- Define retry policy by HTTP method/operation safety, provider response, rate-limit behavior, idempotency, and backoff; never assume 4xx/5xx automatically throw without configured behavior.
- Verify inbound webhook signatures against the exact raw body and required headers before trusting payload fields; validate timestamp/replay window when provider semantics permit.
- Persist provider event IDs and processing outcomes atomically to prevent duplicate or replayed side effects and handle out-of-order events without state regression.
- Implement explicit payment state machines, server-authoritative amount/currency/owner checks, exact money representation, atomic transitions, reconciliation, and idempotent side effects.
- Implement operation-specific idempotency keys and outcome storage for retryable internal/API/provider mutations, with tenant/user/operation scoping and concurrent-request behavior.
- Normalize API and provider errors into validation, authentication, authorization, conflict, rate-limit, temporary dependency, permanent provider, and unexpected categories with safe localized/user/API responses and structured redacted logs.
- Create deterministic fixtures and tests for success, malformed JSON, invalid content type, auth failure, forbidden access, timeout, connection failure, 4xx, 5xx, rate limit, invalid response, retryable/nonretryable error, signature failure, replay, duplicate/out-of-order events, amount/currency/owner mismatch, concurrent idempotency, rollback, and redaction.
- Prevent stray external requests in the test environment and verify all external calls are faked.
