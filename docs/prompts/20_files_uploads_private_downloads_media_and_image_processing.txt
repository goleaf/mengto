# 20. Files, Uploads, Private Downloads, Media, and Image Processing

## Principal-agent role

You are the principal Codex implementation agent responsible for securing and normalizing the complete file lifecycle from validation and storage through transformation, authorization, delivery, replacement, cleanup, deletion, seeding, and testing.

## Mission

Inventory every file category and storage path. Replace unsafe names and public access, centralize validation and image presets, coordinate database/filesystem changes, protect private downloads, eliminate orphan and partial files, optimize delivered media, and prove the entire lifecycle with fake local storage and adversarial tests.

This is not an audit-only, documentation-only, planning-only, or review-only task. Discovery and planning are mandatory intermediate phases. After updating the canonical plan, immediately perform the required implementation, tests, review fixes, documentation synchronization, commit, and safe push directly on `main`.

## Domain-specific guardrails

- Do not trust original filenames, extensions, MIME headers, user-controlled paths, or public URLs as authorization.
- Do not expose private files through unrestricted public storage or cache keys.
- Do not make tests or seeders download files from the internet or contain real private data.
- Do not delete an existing valid file before a replacement is fully validated, stored, persisted, and committed.
- Do not keep a database transaction open during long media processing unless a documented invariant requires it.
- Do not rely on unavailable queues/cron for required cleanup; follow repository runtime constraints.

## Required implementation scope

Complete all applicable work below. Treat the list as a minimum, not as permission to ignore defects discovered in the same scope.

- Create a file-category ownership matrix and centralize disk/path selection through configuration and explicit services/actions.
- Replace original/user-supplied storage names with safe unique generated names while preserving a separately sanitized display name only when needed.
- Validate maximum size, actual content/MIME, allowed format, dimensions/aspect ratio, filename/path, archive contents where applicable, and processing resource limits on the server.
- Store private files outside unrestricted public access and authorize every preview/download at request time, including temporary URL, range, and original-versus-preview access.
- Centralize image/media transformations into versioned presets matching actual UI sizes; normalize orientation, strip unnecessary sensitive metadata, and optimize output.
- Implement watermark, purchased-original, or role-gated access only where current product requirements require it.
- Make create/replace/delete/restore workflows idempotent and compensation-safe so database and filesystem cannot remain inconsistently partial.
- Implement orphan and temporary-file cleanup using queue jobs when permitted or resumable web batches when runtime workers are prohibited.
- Prevent tenant/owner leakage in paths, caches, URLs, notifications, exports, and media delivery.
- Create deterministic local valid/invalid/adversarial fixtures and use fake disks in automated tests and safe demo assets in seeders.
- Add tests for valid upload, MIME/extension spoofing, oversize, dimensions, path traversal, private access, expiry/revocation, replacement, rollback, cleanup, orphans, transformations, metadata, tenant separation, concurrency, and seeded media.
